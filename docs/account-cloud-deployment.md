# 账号、云同步与正式部署边界

前六个产品阶段已经可以完全在本地设备运行。账号与云端属于独立基础设施阶段，不能只靠前端代码安全完成。

## 已完成的准备

- `AccountProvider` 与 `CloudSyncProvider` 使用独立契约，避免页面直接依赖某家云服务。
- 云端会话使用带版本和 revision 的 `CloudSessionEnvelope`，为冲突处理保留空间。
- 图片契约固定为私有资源，不允许自动进入公共素材库。
- `/api/cloud/status` 只返回能力状态，不返回密钥或内部配置。
- `npm run deploy:check` 在构建前检查图片模型、账号、云存储和站点 Origin；不会打印密钥值。

## 尚未完成且不能伪造的部分

需要项目方先选择并创建真实云项目，随后才能实现：

1. 邮箱验证码、手机号或第三方登录；
2. 用户、会话、证据、事件与图片表；
3. 私有对象存储、短期签名 URL 和删除策略；
4. 本地数据首次迁移到云端；
5. 多设备 revision 冲突解决；
6. 正式域名、HTTPS、隐私政策版本与备份；
7. 生产部署平台的环境变量和区域选择。

推荐在选定平台后一次完成数据库迁移、行级权限、私有 Bucket 和登录回调，避免先做一个不安全的“假账号”。

## 上线前最低检查

- 生产环境不渲染 `/dev/*` 页面。
- Qwen Key 仅存在服务端环境变量。
- 所有图片对象默认为 private。
- 删除账号时同步删除图片、分析结果和证据。
- 任何未经复核的模型观察都不能写入偏好证据。
- 通过单元测试、浏览器 E2E、移动端和视觉回归测试。
